# 数据库设计与建表规范

从业务需求到建表 DDL 的标准流程。适用于 MySQL / PostgreSQL / Oracle。

## 一、设计流程

```
业务需求 → 1. 识别实体与关系 → 2. 确定字段与类型 → 3. 设计索引与约束 → 4. 产出 DDL
```

### Step 1：实体识别清单

- 核心实体（名词）：如 变电站、配电变压器、台区、用户、工单、项目
- 关系（动词）：如 变电站在XX区 / 工单属于XX用户
- 关系类型：1:1（罕见）、1:N（常见）、N:M（需中间表）
- 每张表回答：主键是什么？会被哪些表引用？生命周期多久？

### Step 2：字段设计原则

| 原则 | 说明 |
|------|------|
| 单一职责 | 一个字段只存一种含义，不塞 JSON 大对象（除非确需） |
| 最小化冗余 | 可计算的字段（如 金额=单价×数量）不存储，除非有快照需求 |
| 统一度量 | 金额用 DECIMAL，长度用 DECIMAL(m,2)，不用 FLOAT |
| 时间统一 | 统一存 UTC 或本地时间，命名带后缀 `_at`/`_date` 明确粒度 |
| 状态枚举 | 状态字段用 TINYINT/CHAR 存字典码，加注释；不存中文字符串 |
| 版本与软删 | 需要审计时加 `is_deleted`、`version`、`created_by` 字段 |

### Step 3：字段类型选择速查

| 业务数据 | MySQL | PostgreSQL | Oracle |
|---------|-------|-----------|--------|
| 自增主键 | `BIGINT AUTO_INCREMENT` | `BIGINT GENERATED ALWAYS AS IDENTITY` | `NUMBER(19) GENERATED BY DEFAULT AS IDENTITY` |
| 业务ID/关联ID | `BIGINT UNSIGNED` | `BIGINT` | `NUMBER(19)` |
| 金额 | `DECIMAL(18,2)` | `NUMERIC(18,2)` | `NUMBER(18,2)` |
| 百分比 | `DECIMAL(7,4)` | `NUMERIC(7,4)` | `NUMBER(7,4)` |
| 短文本（<255） | `VARCHAR(64/128)` | `VARCHAR(64/128)` | `VARCHAR2(64/128)` |
| 长文本 | `TEXT` | `TEXT` | `CLOB` |
| 日期 | `DATE` | `DATE` | `DATE` |
| 时间戳 | `DATETIME(3)` | `TIMESTAMPTZ` | `TIMESTAMP(3)` |
| 布尔 | `TINYINT(1)` | `BOOLEAN` | `NUMBER(1)` |
| 枚举/状态 | `TINYINT` | `SMALLINT` | `NUMBER(3)` |
| 大字段 | `JSON` / `JSONB`(8.0+) | `JSONB`（推荐） | `JSON`(21c+) / `CLOB` |

### Step 4：索引与约束规划

- **主键**：每表必须有，优先业务无关的自增/雪花 ID
- **外键**：业务强约束可建，高并发写场景推荐应用层保证（性能考量）
- **唯一约束**：业务唯一性（设备编码、工单号）用 UNIQUE KEY
- **普通索引**：WHERE/JOIN/ORDER BY 高频字段；区分度 < 20% 的字段（如性别）不建索引
- **复合索引**：`(a, b, c)` 遵循最左前缀；把等值条件列放前面、范围条件列放后面
- **覆盖索引**：查询列都在索引中，避免回表，适合高频统计

## 二、命名规范

| 对象 | 规范 | 示例 |
|------|------|------|
| 库名 | `业务域_用途` 小写 | `power_dispatch` |
| 表名 | 业务实体，复数/单数统一，`snake_case` | `work_order`、`substation_info` |
| 字段 | `snake_case`，动词+对象 | `created_at`、`due_date`、`is_deleted` |
| 主键 | 统一 `id` | `id` |
| 外键 | `被引用表名_id` | `org_id`、`user_id` |
| 索引 | `idx_表名_字段` / `uk_表名_字段` | `idx_work_order_org`、`uk_work_order_no` |
| 布尔字段 | `is_/has_` 前缀 | `is_deleted`、`has_contract` |

## 三、DDL 模板（三库对照）

### MySQL

```sql
CREATE TABLE IF NOT EXISTS work_order (
    id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键',
    order_no      VARCHAR(32)  NOT NULL COMMENT '工单编号',
    org_id        BIGINT UNSIGNED NOT NULL COMMENT '所属供电所ID',
    order_type    TINYINT      NOT NULL DEFAULT 1 COMMENT '工单类型:1-抢修 2-巡检 3-业扩',
    amount        DECIMAL(18,2) NOT NULL DEFAULT 0.00 COMMENT '金额',
    status        TINYINT      NOT NULL DEFAULT 0 COMMENT '状态:0-待处理 1-处理中 2-已完成 3-已逾期',
    created_at    DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) COMMENT '创建时间',
    updated_at    DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3) COMMENT '更新时间',
    is_deleted    TINYINT(1)   NOT NULL DEFAULT 0 COMMENT '逻辑删除:0-否 1-是',
    PRIMARY KEY (id),
    UNIQUE KEY uk_work_order_no (order_no),
    KEY idx_work_order_org_status (org_id, status),
    KEY idx_work_order_created (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='电力工单表';
```

### PostgreSQL

```sql
CREATE TABLE IF NOT EXISTS work_order (
    id         BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    order_no   VARCHAR(32)  NOT NULL,
    org_id     BIGINT       NOT NULL REFERENCES org(id),
    order_type SMALLINT     NOT NULL DEFAULT 1,
    amount     NUMERIC(18,2) NOT NULL DEFAULT 0,
    status     SMALLINT     NOT NULL DEFAULT 0,
    created_at TIMESTAMPTZ  NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ  NOT NULL DEFAULT now(),
    is_deleted BOOLEAN      NOT NULL DEFAULT FALSE,
    CONSTRAINT uk_work_order_no UNIQUE (order_no)
);
CREATE INDEX idx_work_order_org_status ON work_order (org_id, status);
CREATE INDEX idx_work_order_created ON work_order (created_at);
COMMENT ON TABLE work_order IS '电力工单表';
```

### Oracle 12c+

```sql
CREATE TABLE work_order (
    id         NUMBER(19) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    order_no   VARCHAR2(32)  NOT NULL,
    org_id     NUMBER(19)    NOT NULL,
    order_type NUMBER(3)     NOT NULL DEFAULT 1,
    amount     NUMBER(18,2)  NOT NULL DEFAULT 0,
    status     NUMBER(3)     NOT NULL DEFAULT 0,
    created_at TIMESTAMP(3)  NOT NULL DEFAULT SYSTIMESTAMP,
    updated_at TIMESTAMP(3)  NOT NULL DEFAULT SYSTIMESTAMP,
    is_deleted NUMBER(1)     NOT NULL DEFAULT 0
);
CREATE UNIQUE INDEX uk_work_order_no ON work_order (order_no);
CREATE INDEX idx_work_order_org_status ON work_order (org_id, status);
COMMENT ON TABLE work_order IS '电力工单表';
```

## 四、设计检查清单（交付前自检）

- [ ] 每张表有明确主键，且类型统一
- [ ] 金额/百分比均用 DECIMAL/NUMERIC，未用 FLOAT
- [ ] 所有 VARCHAR 有明确长度上限，未滥用 TEXT
- [ ] 状态、类型字段有注释说明枚举含义
- [ ] 高频查询路径有对应索引，复合索引遵循最左前缀
- [ ] 时间字段统一命名与粒度（`created_at` 带时区/毫秒）
- [ ] 大表（预计千万级+）预留分区/归档策略说明
- [ ] 逻辑删除、审计字段按需设计
- [ ] 表、字段均有中文注释（COMMENT）
