# Oracle 方言速查与国产数据库（达梦/金仓）兼容说明

## 一、基础语法速查

| 操作 | 语法 |
|------|------|
| 分页 | 12c+：`OFFSET m ROWS FETCH NEXT n ROWS ONLY`；旧版：`ROWNUM` 子查询 |
| 字符串拼接 | `a \|\| b`；多行聚合 `LISTAGG(col, ',') WITHIN GROUP (ORDER BY x)` |
| 当前时间 | `SYSDATE`（日期）/ `SYSTIMESTAMP`（带时区） |
| 日期加减 | `SYSDATE + 7`（加 7 天）；`ADD_MONTHS(d, 3)` |
| 取年月 | `EXTRACT(YEAR FROM d)` / `TO_CHAR(d, 'YYYY-MM')` |
| 空值处理 | `NVL(x, 0)` / `COALESCE(x, 0)` |
| 空值排序 | 默认 NULL 最大；`ORDER BY col NULLS FIRST/LAST` |
| 类型转换 | `TO_NUMBER(x)` / `TO_DATE(x, 'YYYY-MM-DD')` / `TO_CHAR(x, 'FM9990.00')` |
| 正则 | `REGEXP_LIKE(col, '^[0-9]+$')` / `REGEXP_SUBSTR` / `REGEXP_REPLACE` |
| 去重计数 | `COUNT(DISTINCT col)` |
| 字符串截取 | `SUBSTR(col, 1, 10)`（从 1 开始） |
| 行号 | `ROWNUM`（分页/取前 N 用） |

## 二、DDL 关键点

```sql
-- 12c+ 自增主键
id NUMBER(19) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,

-- 传统方式（序列 + 触发器），旧系统常见
CREATE SEQUENCE seq_work_order START WITH 1 INCREMENT BY 1;
CREATE OR REPLACE TRIGGER trg_work_order_id
BEFORE INSERT ON work_order FOR EACH ROW
BEGIN
    :NEW.id := seq_work_order.NEXTVAL;
END;
/

-- 注释
COMMENT ON TABLE work_order IS '工单表';
COMMENT ON COLUMN work_order.status IS '状态';
```

- 表名/列名默认大写，双引号包小写名会强制大小写敏感，尽量避免
- 每张表建议 `CREATE INDEX` 于高频查询字段

## 三、分页写法

```sql
-- 12c+（推荐）
SELECT * FROM work_order ORDER BY id
OFFSET 100 ROWS FETCH NEXT 50 ROWS ONLY;

-- 11g 及以下（ROWNUM 经典写法）
SELECT * FROM (
    SELECT t.*, ROWNUM rn FROM (
        SELECT * FROM work_order ORDER BY id
    ) t WHERE ROWNUM <= 150
) WHERE rn > 100;
```

## 四、性能与运维要点

```sql
-- 执行计划
EXPLAIN PLAN FOR SELECT ...;
SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY);

-- 慢 SQL（v$sql）
SELECT sql_id, elapsed_time/1000000 AS seconds, executions,
       sql_text FROM v$sql
WHERE elapsed_time/1000000 > 1 ORDER BY elapsed_time DESC;

-- 收集统计信息（优化器依赖）
EXEC DBMS_STATS.GATHER_TABLE_STATS('POWER', 'WORK_ORDER');

-- 当前会话/锁
SELECT sid, serial#, status FROM v$session WHERE username='APP';
ALTER SYSTEM KILL SESSION 'sid,serial#';
```

- **NULL 排序默认最大**：与 MySQL（默认最小）相反，注意排序一致性
- **空字符串即 NULL**：`''` 与 NULL 等价，判断用 `IS NULL`
- **隐式转换**：VARCHAR2 与 NUMBER 比较注意类型，`'100'` 与 100 比较可能全表扫描
- 行锁机制与 MySQL InnoDB 不同，`UPDATE` 大范围数据锁资源多，分批提交
- 默认读不阻塞写、写不阻塞读（undo 多版本），事务隔离默认 Read Committed

## 五、国产数据库兼容（达梦 DM / 人大金仓 KingbaseES）

电力行业国产化替代常用达梦（DM8）与金仓（KingbaseES V8），两者高度兼容 Oracle 语法。

### 达梦 DM8

- **高度兼容 Oracle**：`NVL`、`SYSDATE`、`||`、`ROWNUM`、存储过程包均可直接用
- 支持 `IDENTITY` 自增（`IDENTITY(1,1)`）与序列两种方式
- 分页可直接用 Oracle 12c 写法或 `LIMIT/OFFSET`（DM8 兼容 MySQL 风格）
- 常用查询：`SELECT * FROM v$sessions;`（会话）、`EXPLAIN` 语法同 Oracle
- 连接工具：DM 管理工具；JDBC 驱动 `dm.jdbc.driver.DmDriver`

### 人大金仓 KingbaseES V8

- 以 PostgreSQL 为内核、兼容 Oracle 语法（兼容模式）
- `SYSDATE`、`NVL`、`||`、`LISTAGG` 可用（兼容模式开启时）
- 分页支持 `LIMIT/OFFSET`（PG 风格）与 Oracle 风格
- `\d` 元命令（psql 风格）查看表结构；`\timing` 看耗时
- 常用查询：`SELECT * FROM pg_stat_activity;`（活动会话）

### 兼容性检查清单

- [ ] 分页语法确认目标库版本（Oracle 12c+ / DM8 / KingbaseES 都支持 FETCH 或 LIMIT）
- [ ] 自增：优先 `IDENTITY`，避免触发器（跨库迁移更简单）
- [ ] 字符串用 `||` 而非 `CONCAT()`（CONCAT 三库均可但参数数量限制不同）
- [ ] 日期函数统一 `SYSDATE`/`CURRENT_DATE` 检查
- [ ] 空字符串语义：Oracle/DM 中 `''` 是 NULL，处理时注意
- [ ] 字段类型：`VARCHAR2`（Oracle/DM） vs `VARCHAR`（金仓）——金仓两者皆可
- [ ] 注释语法 `COMMENT ON` 三库一致，可直接复用

## 六、最佳实践清单

- [ ] 表名/字段名保持大写默认，避免双引号混用
- [ ] 金额用 `NUMBER(18,2)`，不用 `FLOAT`
- [ ] 时间用 `TIMESTAMP(3)`，涉及时区用 `TIMESTAMP WITH TIME ZONE`
- [ ] 大分页用 `OFFSET/FETCH`（12c+）或 ROWNUM 改写，不用 `ROWNUM > n` 直接过滤（结果为空）
- [ ] 生产变更走 `DBMS_STATS` 收集统计信息后验证执行计划
- [ ] 国产库迁移前用兼容性检查清单逐项验证
